# Session 2026-10-10: full-pixel replay and readable startup lettering

The same captured 800M guest graphics stream now produces readable **Sony
Computer Entertainment** lettering, cloud detail and colored lights in an
explicitly selected 640x256 logical framebuffer. This is genuine additional
raster detail, not a larger/sharpened copy of the earlier image. It is a visible
startup-title checkpoint, not a verified complete animation, display scanout,
game compatibility or performance on physical Vita.

## Isolating the blurry preview

The default 160x112 renderer converts GS 12.4 coordinates to a quarter grid and
replicates each accepted sample into a 4x4 native tile. Thin guest line geometry
can collapse into a one-row white band there. The 800M stream already contains
2,808 line draws; it did not need a new BIOS run, arbitrary packet delay or extra
VU work to produce readable lettering. The prior 640x448 linear probe also
crossed the 640x256 drawing surface into neighboring framebuffer storage.

Added the separate host-only `ps2graphics_native` library from Gif/Gs sources,
with PUBLIC `PS2VITA_GS_RASTER_SCALE=1`, and `ps2gif_replay_native`. Every linked
consumer uses the matching scale definition. The normal core and Vita keep
scale 4. XYZ scaling, sprite bounds, scissor mapping, UV prestep, color-target
reads/writes and pixel-watch footprints use the same scale; FRAME/TBW block
units, texel bytes and raw guest attributes do not change. Off-viewport sprite
loops are bounded before sampling, preserving accepted default writes.

Scale 1 provides a 640x448 raster viewport and one write per native pixel. It
still uses existing integer-vertex truncation, interpolation, nearest filtering,
logical linear storage and approximate depth/GS behavior. Native pixel density
is not native GS correctness. Fixed-quarter sprite source probes stay 160x64 at
4-pixel spacing, explicitly independent of the raster grid.

## Explicit, non-mutating surface selection

Both replay executables now support:

```sh
--linear-framebuffer FILE --dispfb HEX --linear-size WIDTHxHEIGHT
```

All flags must be present together. Strict parsing validates sample-scale
divisibility, PSMCT32/24, nonzero stride, origin/width within the row, and the
complete native region's last byte within 4 MiB without wrap. Arithmetic widens
before coordinate addition. Selection is read-only through `Gif::read_local32`
after complete container validation; it never binds or changes the draw target.
The output is included in canonical/hardlink alias protection, and logs selection,
native/sample dimensions, raw-word hash and nonblack RGB sample count. Privileged
GS registers are not captured in this stream; DISPFB is an explicit externally
observed selection, not inferred display scanout or an interlace reconstruction.

At the saved 800M endpoint the tracer recorded enabled DISPFB2 `1400` (base 0,
width 640), whereas the active draw FRAME is `000A00F0` (base `001E0000`). The
native selection `--dispfb 1400 --linear-size 640x256` excludes the known neighboring
